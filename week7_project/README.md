# Predicting Employee Attrition — IBM HR Analytics Dataset

to leave the company, using the IBM HR Analytics Employee Attrition dataset.

## How to run

1. Create a virtual environment (recommended) and install dependencies:
   ```bash
   python3 -m venv venv
   source venv/bin/activate      # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. Launch Jupyter and open the notebook:
   ```bash
   jupyter notebook notebook.ipynb
   ```
   Then run all cells top to bottom (`Cell > Run All`).

   Alternatively, to re-run headlessly from the command line:
   ```bash
   jupyter nbconvert --to notebook --execute --inplace notebook.ipynb
   ```

3. To regenerate the notebook itself from scratch (e.g. after editing `build_notebook.py`):
   ```bash
   python3 build_notebook.py
   jupyter nbconvert --to notebook --execute --inplace notebook.ipynb
   ```

## How to reuse the trained model

```python
import joblib
import pandas as pd

bundle = joblib.load("model.pkl")
model = bundle["model"]                  # trained LogisticRegression
scaler = bundle["scaler"]                # fitted StandardScaler
feature_columns = bundle["feature_columns"]  # exact column order the model expects

# `new_df` must first go through the same cleaning steps as in the notebook's
# Phase 2 (drop EmployeeCount/Over18/StandardHours/EmployeeNumber, encode
# Attrition/Gender/OverTime as 0/1, one-hot encode the remaining categoricals),
# then be aligned to the training columns before scaling:
new_df = new_df.reindex(columns=feature_columns, fill_value=0)
new_df_scaled = scaler.transform(new_df)
predictions = model.predict(new_df_scaled)          # 0 = stays, 1 = predicted to leave
probabilities = model.predict_proba(new_df_scaled)[:, 1]  # attrition risk score, 0-1
```

## Interpreting the results

- **Class imbalance**: only ~16% of employees in this dataset actually left the company
  (`Attrition = Yes`). We balanced the *training* data with SMOTE, but evaluated on an
  untouched, still-imbalanced test set — the realistic scenario a deployed model would face.
- **Why Logistic Regression, not the highest-accuracy model**: Random Forest scored
  highest on accuracy/ROC-AUC but only caught ~30% of employees who actually left (recall).
  Logistic Regression catches ~60% of them with the best F1-score of all 4 models tested.
  For an HR retention use case, missing at-risk employees is costlier than a false alarm,
  so we optimized for recall/F1 on the minority class rather than headline accuracy.
- **Metrics reported**: Accuracy, Precision, Recall, F1-score, ROC-AUC, and confusion
  matrices — all computed on a held-out 20% test set that the model never saw during
  training.
- **Feature importance**: see `notebook.ipynb` (Phase 5) or `report.pdf` for the full
  breakdown. In short — `OverTime`, tenure-related features (`TotalWorkingYears`,
  `YearsWithCurrManager`), `BusinessTravel`, and `JobRole` are the strongest, most
  consistent drivers of attrition across both Logistic Regression and Random Forest.
- A prediction's `probabilities` output (0 to 1) can be used as a continuous "attrition
  risk score" for prioritizing HR outreach, rather than only using the hard 0/1 label.
